# Compatibility and standards

This is a static audit of the packaging and runtime assumptions. It is not a
claim that every distribution has been tested on real hardware.

## Supported platforms

| Platform | Package | Status |
| --- | --- | --- |
| Arch Linux | `distro/arch/PKGBUILD` | Tested during development |
| Debian 13 | `debian/` | Packaging present; needs a Debian build/test pass |
| Ubuntu 25.10 | `debian/` | Packaging present; Rust 1.85 or newer required |
| Fedora 42+ | `distro/rpm/clash-kde.spec` | Packaging present; needs a Fedora build/test pass |
| openSUSE Tumbleweed | `distro/rpm/clash-kde.spec` | SUSE dependency branches present; needs an openSUSE build/test pass |
| openSUSE Leap 15.x | — | Not supported: no Plasma 6/KF6 stack |

Requirements: Plasma 6, Qt 6.6+, KF6 6.0+, Rust 1.85+ (edition 2024), Linux
with systemd, a session bus, the system bus, polkit, and `mihomo` on `PATH`.
TUN additionally requires the root-owned `/usr/bin/mihomo`.

## openSUSE specifics

The openSUSE Tumbleweed `mihomo` package:

- installs `/usr/bin/mihomo`;
- ships **no** `country.mmdb`/`geosite.dat` under `/usr/share`;
- also installs a system service named `mihomo.service` using mixed port 7890
  and controller port 9090 with `DynamicUser=yes` and `StateDirectory=mihomo`.

Therefore:

1. The system service must be stopped before the per-user core can bind the
   same ports: `sudo systemctl disable --now mihomo`. The service now reports a
   port conflict explicitly and `--diagnose` prints the `mihomo.service` state.
2. Without v2ray geodata, mihomo downloads MMDB/GeoSite on first start and may
   appear to hang. Install `v2ray-core`, which provides
   `/usr/share/v2ray/geoip.dat` and `geosite.dat`; the service copies them and
   writes `geodata-mode: true` automatically. Alternatively put a
   `country.mmdb` in `~/.config/mihomo/`.
3. openSUSE uses AppArmor. The distribution `mihomo` package does not ship a
   profile, but a locally added profile can deny access to the per-user runtime
   directory. Check `sudo aa-status` and `journalctl -k | grep -i apparmor`.

The RPM spec selects SUSE package names when `%{?suse_version}` is set. It pins
`rust1.99` because that is the versioned Rust package in Tumbleweed; update the
BuildRequires when Tumbleweed moves to another `rust1.x`.

## TUN routing

TUN route layout is configurable in `~/.config/clash-kde/config.toml`:

- `tun_route_table` (default 2022) and `tun_rule_index` (default 9000) are
  written as mihomo's `iproute2-table-index` / `iproute2-rule-index`.
- `tun_exclude_private` (default true) keeps Tailscale, private LAN, IPv4
  link-local, and IPv6 link-local traffic out of TUN.
- `tun_health_secs` (default 5) controls the running route-health probe.

The probe currently checks **IPv4 only** (`ip -4 rule show` and
`ip -4 route show table ...`). It requires `iproute2`; if `ip` is unavailable,
the route is reported as unknown rather than failed. A route is considered
ready when the configured rule exists and the table has either a `default`
route or the `0.0.0.0/1` + `128.0.0.0/1` pair. The service waits up to 30
seconds at startup and rechecks periodically; a lost route is shown in the
Status page and in `clash-kde --diagnose`.

Authorization is stored per UID under `/var/lib/clash-kde/tun`. It is removed
when TUN is turned off, not by a normal service shutdown, so a later login can
restore a previously enabled TUN. While the grant exists, any process running
as the same UID can call `SpawnTun`; this matches the per-user threat model and
should be reviewed before granting TUN to a shared account.

## Freedesktop / Linux standards

| Standard | Status | Notes |
| --- | --- | --- |
| FHS paths | Met | `/usr/bin`, `/usr/lib`, `/usr/share`, `/var/lib`; no `/opt` assumptions |
| XDG Base Directory | Mostly met | Config/data use `XDG_CONFIG_HOME`/`XDG_DATA_HOME`; `session_bridge` still assumes `~/.config` and `~/.local/share` for *other* users |
| systemd units | Met | Session and system `Type=dbus` units, user preset, `ExecStopPost` proxy recovery |
| D-Bus | Met | Session `org.kde.clashkde.Manager`, system `org.kde.clashkde.Admin`, activation files and policy |
| polkit | Met | Three actions, `pkcheck` with caller bus name, no password in the D-Bus payload |
| Desktop entry | Met | KCM desktop file is generated by `kcmutils_add_qml_kcm`; applet metadata is embedded |
| AppStream | Missing | No `metainfo.xml`; software centers will not show rich metadata |
| gettext | Met | UI has 10 catalogs; Rust returns stable error codes translated by the KCM/applet, while logs and diagnostics stay English |
| SPDX | Met | C++/QML/applet files and all `src/*.rs` files carry SPDX identifiers |
| Accessibility | Mostly met | Standard Qt/Kirigami controls; applet compact view has `Accessible.name`/role |
| HiDPI | Met | Kirigami units; no hard-coded pixel sizes |
| CI | Met | `.github/workflows/ci.yml` runs formatting, tests, clippy, QML lint, and the KCM build on Arch Linux |
| Reproducible RPM build | Partial | `cargo build` needs network; OBS/Koji need vendored crates |

## Portability limits

- `pkcheck`, `mihomo`, and `clash-kde` are looked up at fixed FHS paths
  (`/usr/bin/...`). NixOS, Guix, and non-FHS prefixes are not supported.
- The Arch `PKGBUILD` builds from a repository checkout (`startdir/../..`) and
  has no `source=()`/checksums. It is a local `makepkg` recipe, not an AUR-ready
  or reproducible source package.
- Debian has no `mihomo` package in its archive, so `mihomo` is a `Recommends`
  in `debian/control`; install it separately.
- The RPM and Debian builds invoke `cargo` with network access. A fully offline
  package build needs `cargo vendor` and a vendored-source setup.
- The application targets a single-user desktop session. The root helper is
  intentionally narrow, but it assumes systemd, polkit, and a writable
  `/var/lib/clash-kde`.
